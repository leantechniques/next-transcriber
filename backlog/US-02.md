# US-02: GitHub Actions PR Verification Pipeline

## User Story
As a **developer on the Next Transcriber team**
I want **automated tests to run on every pull request**
So that **I have confidence that my changes don't break the codebase before merging**

## Business Value

**Problem We're Solving:**
Currently, there are no automated quality gates before code reaches the main branch. Reviewers must manually pull, install, and run tests for every PR, which creates:
- Manual verification burden on reviewers
- Risk of forgetting to run tests before merging
- Potential for broken main branch
- Slow feedback loops (only discover test failures after PR review)

**Value Delivered:**
- **Faster feedback:** Know within 2 minutes if PR breaks tests (vs. waiting for manual review)
- **Confidence:** Trust that approved PRs won't break the codebase
- **Time savings:** No manual "pull, install, test" cycle for each PR
- **Quality culture:** Automated enforcement of testing standards from day one
- **Foundation for growth:** Sets pattern for future CI checks (linting, type-checking, E2E tests)

**ROI:** Even one prevented bug saves more time than automation cost (GitHub Actions free tier: 2,000 minutes/month)

## Technical Considerations

### High-Level Approach
- Use GitHub Actions with standard Node.js workflow
- Run on Ubuntu latest runner
- Use `actions/checkout@v4` and `actions/setup-node@v4`
- Cache npm dependencies for faster builds (use `actions/cache` or setup-node's built-in cache)
- Target <2 minute total CI time for current test suite

### Dependencies
- **Existing:** Vitest test suite from US-01
- **Existing:** npm scripts: `npm run test`, `npm run build`
- **Required:** GitHub Actions workflow file
- **Required:** Branch protection rules (manual GitHub configuration)

### Architecture Fit
- Aligns with "Definition of Done" requirement that all tests pass
- Supports Test-Driven Development (TDD) workflow
- Foundation for future quality checks (linting, type-checking, coverage)
- No changes to existing code or test structure needed

## Implementation Notes

### Workflow Structure (`.github/workflows/pr-verify.yml`)
```yaml
name: PR Verify
on:
  pull_request:
    branches: [main]

jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - Checkout code
      - Setup Node.js 20.x with npm cache
      - Log versions (node --version && npm --version)
      - Install dependencies (npm ci)
      - Run tests (npm run test)
      - Run build verification (npm run build)
```

### Backend Considerations
- **Current:** Single health check endpoint, minimal complexity
- **Future:** Will need to handle API mocking for YouTube integration (US-03+)
- **Security:** No secrets required currently, but establish pattern for future (GitHub Secrets)
- **Performance:** Test suite runs in <10 seconds, CI should complete in <2 minutes

### Frontend Considerations
- **Testing:** React Testing Library with jsdom (sufficient for current scope)
- **Build Verification:** `npm run build` catches Server Component errors
- **TypeScript:** Consider explicit type check step (`npx tsc --noEmit`)
- **Visual Regression:** Not needed yet (defer until US-05+ when actual UI exists)
- **Developer Impact:** Positive - catches errors early, minimal friction

### QA/Testing Considerations
- **False Positives Risk:** Use exact Node version to prevent environment mismatches
- **False Negatives Risk:** Ensure workflow fails correctly on test failures
- **Flaky Tests:** Zero tolerance - tests must be deterministic
- **Performance:** Cache `node_modules` to keep CI under 3 minutes
- **Debuggability:** Clear error messages showing which test failed and why

## Edge Cases to Handle

### Installation Edge Cases
- Fresh CI environment (no cache) → Complete in <3 minutes
- Cached dependencies exist → Complete in <1 minute
- `package-lock.json` missing → CI fails with clear error
- npm registry timeout → Retry logic (GitHub Actions automatic retry)

### Test Execution Edge Cases
- All tests pass → CI succeeds (green checkmark)
- One test fails → CI fails, shows which test failed
- No tests found → CI should warn or fail (protect against accidental deletion)
- Test file syntax error → CI fails with compilation error

### GitHub Actions Edge Cases
- Multiple commits pushed rapidly → CI runs once on latest commit
- Force push to PR branch → CI re-runs on new commit
- PR from fork (external contributor) → CI runs (no secrets exposed currently)
- Developer clicks "Re-run jobs" → Workflow re-runs without new commit

### Developer Workflow Edge Cases
- CI failing, can't reproduce locally → Documentation helps diagnose (Node version, clean install)
- WIP commit pushed → CI runs and may fail (expected, not a problem)
- PR marked as draft → CI still runs (catches issues early)
