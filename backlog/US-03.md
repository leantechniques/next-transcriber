# US-03: Transcription UI Foundation

## User Story

As a **content creator or researcher**
I want **a clean UI to input YouTube URLs and view transcription results**
So that **I understand how the transcription workflow will work and can prepare to use the tool**

---

## Business Value

### Problem We're Solving
Currently, users have a scaffolded Next.js application with CI/CD but **no user interface to interact with**. Without a UI, we cannot progress to implementing actual transcription functionality or gather early user feedback on the workflow.

### Value Delivered
- **First tangible interaction**: Users can see and interact with the product for the first time
- **Clear workflow established**: UI establishes the mental model: paste URL → transcribe → view results
- **Foundation for MVP**: Minimum viable interface needed to deliver transcription value
- **Unblocks development**: Future transcription features (US-04+) need this UI foundation
- **Early feedback opportunity**: Validate workflow before investing in complex transcription logic
- **Quality from day one**: Individually tested components signal reliability

### Strategic Alignment
This is a **foundational enabler** - necessary but not sufficient for value delivery. Real user value comes when US-04 (transcription functionality) integrates with this UI.

**ROI**: 2-3 days investment now prevents costly rework later when adding transcription logic.

### Technology Choices

**Styling:** Tailwind CSS
- Modern default for Next.js projects
- Rapid development with utility classes
- Built-in responsive design
- Excellent tree-shaking (only ships used classes)
- Easy theming and customization

**State Management:** React `useState`
- Simple form state (URL, output text, loading)
- No need for complex state management yet
- Centralized in `TranscriptionForm` component

**Client vs Server Components:**
- `page.tsx`: Server Component (SEO, metadata)
- All form components: Client Components (need interactivity)
- Clear `'use client'` directives at component top

**API Routes:**
- Next.js 15 App Router route handlers
- TypeScript for request/response types
- Proper HTTP status codes (200, 400, 501)
- Error response format consistent

### Props Interfaces

```typescript
// UrlInput
interface UrlInputProps {
  value: string;
  onChange: (value: string) => void;
  disabled?: boolean;
  maxLength?: number; // Default: 2048
}

// TranscribeButton
interface TranscribeButtonProps {
  onClick: () => void;
  disabled?: boolean;
  loading?: boolean; // For future loading state
}

// TranscriptionOutput
interface TranscriptionOutputProps {
  value: string;
  placeholder?: string;
}

// TranscriptionForm (no props - top-level container)
```

### State Management Pattern

```typescript
// TranscriptionForm.tsx
'use client';

export function TranscriptionForm() {
  const [url, setUrl] = useState('');
  const [output, setOutput] = useState('');
  const [isTranscribing, setIsTranscribing] = useState(false);

  const handleTranscribe = () => {
    setIsTranscribing(true);
    // Mock delay to simulate processing
    setTimeout(() => {
      setOutput('Transcription functionality coming soon. This is where your video transcription will appear.');
      setIsTranscribing(false);
    }, 500);
  };

  return (
    <div>
      <UrlInput
        value={url}
        onChange={setUrl}
        disabled={isTranscribing}
      />
      <TranscribeButton
        onClick={handleTranscribe}
        disabled={!url || isTranscribing}
        loading={isTranscribing}
      />
      <TranscriptionOutput
        value={output}
        placeholder="Your transcription will appear here..."
      />
    </div>
  );
}
```

## Backend Considerations

### API Contract

**Validation Endpoint:**
```typescript
// POST /api/transcribe/validate
// Request
{
  "url": "https://www.youtube.com/watch?v=VIDEO_ID"
}

// Response (200 - Valid)
{
  "valid": true
}

// Response (400 - Invalid)
{
  "error": {
    "code": "INVALID_INPUT",
    "message": "URL must be a string under 2048 characters"
  }
}
```

**Transcription Endpoint (Stub):**
```typescript
// POST /api/transcribe
// Request
{
  "url": "https://www.youtube.com/watch?v=VIDEO_ID"
}

// Response (501 - Not Implemented)
{
  "error": {
    "code": "NOT_IMPLEMENTED",
    "message": "Transcription service not yet implemented"
  }
}
```

### Security Considerations

**Input Validation:**
- Always validate input length (max 2048 characters)
- Always validate input type (must be string)
- Sanitize URLs before processing
- Never trust client-side validation alone

**XSS Prevention:**
- React's JSX escapes by default
- Never use `dangerouslySetInnerHTML` for user input
- Validate URLs using `URL` constructor

**CSRF Protection:**
- Not needed yet (no authentication, no cookies)
- Future: Use CSRF tokens or SameSite cookies

**Rate Limiting:**
- Not implemented in this story
- Future: Add rate limiting to prevent abuse (10 requests/minute per IP)

## QA/Testing Considerations

### Testing Strategy

**Unit Tests (Automated):**
- Each component tested in isolation
- Mock dependencies (clipboard API)
- Test all props and state combinations
- Test edge cases (empty, long text, special characters)

**Integration Tests (Automated):**
- Test `TranscriptionForm` composition
- Test component interactions
- Test full user flow (type URL → click → copy)

**Accessibility Tests (Automated):**
- Run axe-core on all components
- Verify ARIA attributes
- Test keyboard navigation in tests

**Manual Testing:**
- Cross-browser (Chrome, Firefox, Safari, Edge)
- Mobile devices (iOS Safari, Chrome Android)
- Screen reader (VoiceOver or NVDA)
- Responsive design verification

### Edge Cases to Test

**URL Input:**
- Empty input
- Whitespace-only input
- Extremely long URLs (>2000 characters)
- URLs with special characters
- Multiple URLs pasted at once
- YouTube URL variations (standard, shortened, mobile, embedded, with timestamp)

**Transcribe Button:**
- Click when disabled
- Double-click (should only trigger once)
- Keyboard activation (Enter/Space)
- Rapid clicks

**Transcription Output:**
- Empty state
- Very long text (>50,000 characters)
- Text with special characters
- Multi-line text
- Right-to-left text

**Manual Copy (Native Browser):**
- User can select text with mouse/keyboard
- User can copy using Ctrl/Cmd+C or right-click context menu

**Responsive:**
- Mobile portrait (375x667)
- Mobile landscape (667x375)
- Tablet (768x1024)
- Desktop (1920x1080)
- Text zoom 200%
